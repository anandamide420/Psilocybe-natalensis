Run recovery report · re-basecall & re-demultiplex

Re-analysis with the correct barcode kit: four P. natalensis libraries, two extraction methods, duplicates of each.

YH_31Jul2026_Mushroom_Genome_Sequencing was acquired with SQK-MAB114-24 selected in MinKNOW when the library was SQK-RBK114-24. Live demultiplexing failed almost completely. Re-basecalling the POD5 with the correct kit — and a newer model — recovered the barcodes without re-sequencing anything. With the libraries separated, the run does what it was built to do: compare two DNA extraction methods on Psilocybe natalensis, in duplicate.

The unclassified bin is mostly junk, not lost samples. Only 14% of its reads clear Q10, against 76–88% for the four real barcodes — so little genuine data is trapped there. Twelve further barcode bins picked up 1–8 reads each; that is classifier noise, and the pipeline excludes them below its 100-read floor.

02 · Reference

Mapped against the wrong species, by ~12%

Coverage figures are not usable as coverage

The libraries are P. natalensis; the only reference on hand is P. cubensis (GCF_017499595.1). Reads that map do so at 88.1–88.5% identity — the expected distance between congeneric Psilocybe, not a problem with the data. But it means only ~29–47% of reads find an anchor at all, so every depth and coverage number in this report is a lower bound against the wrong genome. Real per-sample coverage needs a P. natalensis reference or a de novo assembly.

The data agrees with a single species across all four libraries. Identity peaks land within 0.4% of each other, GC sits at 49.1–50.2% throughout, and each distribution is one clean peak with no second mode near 99% — so no library carries a contaminating population. Within each library, coverage is spread evenly across all 13 chromosomes rather than being patchy by contig, which is what species divergence looks like rather than a partial genome.

This also settles the mapping-rate spread. It is not about sample identity — all four are the same organism. It tracks fragment length, which is the variable this run was built to test.

04 · Extraction method

Chloroform gave roughly twice the read length. Nothing else separated.

Two methods, two libraries each. With duplicates in hand, a method effect has to be larger than the spread between replicates to mean anything — which lets us say clearly which differences hold up and which do not.

Zymo N50Chloroform N50mean read length

Read-length N50 separates cleanly. Zymo returned 3.1 and 5.0 kb; chloroform returned 7.6 and 9.9 kb. The two groups do not overlap, and the gap between methods (~2×) is wider than the gap between replicates — consistent with column binding and elution shearing long fragments that a chloroform extraction leaves intact.

Yield did not separate. Zymo gave 75.0 and 220.4 Mb; chloroform gave 238.0 and 25.0 Mb. Replicate spread swamps any method difference — a ~3× and a ~10× gap within each pair — so this run cannot say which method yields more. Pass rate (76–88%), mapping rate (29–47%) and mean read length (1.6–3.9 kb) overlap between groups too, so N50 is the only metric here with a clean method signal.

Two libraries per method. Directional, not conclusive — enough to justify chloroform where fragment length matters, not enough to publish a rate.

Barcode 16 is bimodal, and its 9.9 kb N50 flatters it. 20% of its passing reads are ~100 bp and 30% are under 130 bp, against 2% at 100 bp for its chloroform duplicate barcode 15. A pile of very short fragments alongside a genuinely long tail pulls the mean down to 2.8 kb while leaving N50 the highest in the run — and it explains why bc16 maps at only 29% despite that N50, since ~100 bp reads cannot anchor in a genome 12% divergent from the reference. Since bc15 came through the same extraction cleanly, this looks like something specific to that one library rather than a property of the chloroform method.

11 · Reference choice

P. cubensis is the closest reference available — by a wide margin

Since the depth and coverage numbers above are capped by using a different-species reference, the obvious question is whether a better one exists. It does not. Each library was sketched with mash and ranked against one representative genome for every one of the 15 Psilocybe species in NCBI. P. cubensis wins in all four, sharing 6–9× more k-mer hashes than the runner-up.

There is no P. natalensis assembly in NCBI at all — 145 Psilocybe assemblies across 15 species, none of them natalensis. So ~88% identity and a 29–47% mapping rate is the floor for any public reference, and the only route past it is an in-house P. natalensis assembly, which needs depth this run does not have.

Read the ranking, not the absolute distance. 2% ONT error destroys 21-mers, so mash estimates ~82% ANI where alignment measured 88%. The ordering is robust; the magnitude is not. Distances also come from coverage-equalised sketches (25 Mb each) — without that, mash ranks libraries by depth rather than sequence.

Library vs library — no resolvable structure

Equalised for coverage, every pair sits within 0.006 of every other. Consistent with one organism throughout, but it also means mash cannot confirm which libraries are the duplicate pairs at this depth — technical noise swamps the biology. Before equalising, the two deepest libraries looked closest, which was the coverage confound and nothing else.

Methylation

  • The original run was not modified. The pipeline reads only pod5/ and refuses to start if its output directory resolves inside the MinKNOW run folder.
  • Methylation was skipped. 6mA + 4mC_5mC run in a single pass for ~2× the GPU time, but at this depth only genome-wide fractions would be meaningful, not per-site calls. Enabling it re-runs all 46 basecalling tasks — -resume does not make it a cheap addition.
  • Next step: a P. natalensis reference. Everything alignment-derived here is throttled by mapping P. natalensis reads onto a P. cubensis genome. With one, the ~29–47% mapping rate should jump and the depth and coverage columns become real numbers. Failing that, the two chloroform libraries have the fragment length to attempt a de novo assembly, though not the depth.
